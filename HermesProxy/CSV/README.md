# HermesProxy/CSV — static data

Data the proxy loads at startup (`World/GameData.cs`, `World/AuraSpellRemap.cs`). Not all of it
comes from the client's DB2 tables: a large part is hand-made, written to fix one behaviour at a
time, and cannot be regenerated. This file says which is which.

## Naming

A trailing digit is an expansion, not a build: `Item3.csv` is read for any WotLK-expansion client.

| suffix | modern client | built with |
|---|---|---|
| `1` | 1.14 Classic Era | `--build 1.14.2.42597` |
| `2` | 2.5 TBC Classic | `--build 2.5.3.41750` |
| `3` | 3.4.3 WotLK Classic | `--build 3.4.3.54261` |
| `4` | 4.4.2 Cataclysm Classic | `--build 4.4.2.60895` |

Each loader picks the digit from **one side** of the connection, and the two can differ (a 2.5
client in front of a vanilla server, a 4.4.2 client in front of a 3.3.5a server):

- **client** — `ModernVersion.ExpansionVersion`: facts about the modern client's own tables.
- **server** — `LegacyVersion.ExpansionVersion`: facts about the legacy server's data.
- **fixed** — one file for every build.

Most loaders skip a file that is missing, so an absent family turns a feature off rather than
failing startup.

## Regenerating

`scripts/build-csv-from-db2.py` builds every family that comes from DB2, from wago.tools exports
(cached under `.cache/db2/<build>/`):

```bash
python scripts/build-csv-from-db2.py --audit --all 3                     # drift, writes nothing
python scripts/build-csv-from-db2.py --all 4 --build 4.4.2.60895         # write the *4 set
```

Every `*3` recipe reproduces its committed file exactly (`--audit --all 3`). The loaders parse by
column index, so a recipe pins the column order and fails on a renamed source column; values are
re-encoded into the integer type each loader parses (`LOADER_TYPES`).

Then load the set through the proxy's own loaders, for the build it is for:

```bash
dotnet build
HERMES_TEST_CSV_LOAD=1 HERMES_TEST_MODERN_BUILD=V4_4_2_60895 \
    dotnet HermesProxy.Tests/bin/Debug/net10.0/HermesProxy.Tests.dll \
    --filter-class HermesProxy.Tests.World.GameDataCsvLoadTests
```

It caught `Hotfix/ItemEffect4.csv`: 4.4.2 is the first export with a `TriggerType` of -1, and
that hotfix loader reads the column as a byte.

bonuses into plain stats, so the 4.4.2 client has no effect to compare them against.

## Hand-made, read for the client's expansion

Written by hand, each to fix one behaviour; the commit that added a row usually explains it.
Most mix two sides: an id from the legacy server and an id in the modern client's tables.

| family | suffixes | what it holds |
|---|---|---|
| `ItemIdToDisplayId` | 1 2 3 4 | server item → display id. About 14.5k of the 46k `*3` rows agree with the client's tables; the rest are server and custom items |
| `MeleeSpells` | 1 2 3 4 | spells that hit on the next swing; 218 of the 295 `*3` ones carry the client's next-swing attribute |
| `AutoRepeatSpells` | 1 2 3 4 | the auto-repeat spells (shoot, wand) |
| `Gems` | 2 3 4 | gem enchantment → gem item |
| `CurrencyTypes` | 3 4 | server currency item → client currency id |
| `AreaTriggerRemap` | 3 4 | client area trigger id → the server's id for the same trigger |
| `AreaTriggerProximity` | 3 4 | server area triggers the client never reports, fired by position |
| `AuraSpellRemap` | 3 4 | server aura spell id → the client's |
| `WorldMapAreaIDToUiMapID` | 3 4 | server world map area → client `UiMap` id |
| `Hotfix/AreaTrigger` | 1 2 3 4 | area trigger rows sent to the client as hotfixes |

**The `*4` copies are for the 4.4.2 client in front of a 3.3.5a server**, the protocol test bed.
`carry` in the script copies the `*3` rows and drops any whose client-side id the 4.4.2 tables no
longer have. Seven `Gems` items and `UiMap` 1416 (Alterac Mountains, merged into Hillsbrad by
Cataclysm) were dropped; everything else exists in 4.4.2. Behind a 4.3.4 server the server-side
half of these rows needs redoing.

## One file for every build

`AreaNames`, `Battlegrounds`, `BuildAuthSeeds`, `ChatChannels`, `CreatureDisplayInfo`,
`DispellSpells`, `LearnSpells`, `MountAuras`, `RaceFaction`, `TotemSpells`,
`WmoGameObjectDisplays`. Hand-made or from older sources; none is regenerated by the script.

`BarberShopStyle3.csv` belongs here too: it is a `BarberShopStyle` export, but the loader opens it
by that exact name for every build.

## Custom hotfix rows (`*1`, `*2`)

`Hotfix/CreatureDisplayInfo`, `CreatureDisplayInfoExtra`, `CreatureDisplayInfoOption`,
`ItemDisplayInfo`, `ItemSparse`, `SkillLine`, `SkillLineAbility`, `SkillRaceClassInfo`, `Spell`,
`SpellAuraOptions`, `SpellEffect`, `SpellLevels`, `SpellMisc`, `SpellName`: hand-made rows the proxy
sends as hotfixes so the 1.14 and 2.5 clients know server items, creatures and spells their own
tables lack. None exists for 3.4.3 or 4.4.2.

## Unused

`MountSpells3.csv`: nothing reads it. `LoadMountSpells` reads `Hotfix/Mount{N}.csv`.
